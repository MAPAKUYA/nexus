# Как выложить NEXUS на GitHub (пошагово, без командной строки)

**Что делается автоматически, а что вручную**
- Вручную, один раз: создать страницу проекта на GitHub и загрузить туда код.
- Автоматически: установщик, портативный архив и контрольные суммы собирает сам GitHub на настоящей Windows,
  когда вы ставите на проекте «метку версии» (тег `v1.0.0`).

## Часть 1. Подготовка (один раз)
1. Зарегистрируйтесь на https://github.com (если аккаунта ещё нет). Запомните свой **логин**.
2. Установите программу **GitHub Desktop**: https://desktop.github.com и войдите в неё под своим аккаунтом.
3. Распакуйте `NEXUS-source-1.0.0.zip` в удобную папку, например `C:\Projects\`. Должна получиться папка
   `C:\Projects\nexus`, внутри которой сразу лежат `package.json`, `README.md`, `src`, `crates` и т. д.
4. Замените в файлах слово `OWNER` на ваш логин GitHub (это ссылки на ваш репозиторий). Самый простой путь:
   откройте PowerShell **в папке `nexus`** (в проводнике: клик по адресной строке, ввести `powershell`, Enter)
   и выполните, подставив свой логин вместо `ВАШ_ЛОГИН`:
   ```powershell
   Get-ChildItem -Recurse -File -Include README.md,README.ru.md,package.json,Cargo.toml |
     ForEach-Object { (Get-Content $_.FullName -Raw -Encoding UTF8).Replace('OWNER','ВАШ_ЛОГИН') | Set-Content $_.FullName -Encoding UTF8 -NoNewline }
   ```
   Если боитесь ошибиться, пропустите шаг: сайт заработает и так, но ссылки в README будут вести в никуда — их
   можно поправить позже, прямо на сайте GitHub (кнопка с карандашом).

## Часть 2. Загрузка кода
1. В GitHub Desktop: **File → Add local repository…** → выберите папку `C:\Projects\nexus`.
   Появится сообщение, что это ещё не репозиторий, — нажмите **create a repository**.
2. Name: `nexus`. Поля Git Ignore и License оставьте **None** (они уже есть в проекте). Нажмите **Create repository**.
3. Слева будет список файлов. Внизу слева в поле **Summary** напишите `NEXUS 1.0.0` и нажмите **Commit to main**.
4. Нажмите **Publish repository** (сверху). **Снимите галочку «Keep this code private»** и нажмите **Publish**.
5. Откройте https://github.com/ВАШ_ЛОГИН/nexus → вкладка **Actions**. Если GitHub попросит разрешить запуск
   рабочих процессов — разрешите. Через 10–20 минут на вкладке должна появиться зелёная галочка у проверки **CI**.
   Если красный крестик — откройте его, скопируйте текст ошибки и пришлите мне.

## Часть 3. Выпуск версии 1.0.0
1. В GitHub Desktop откройте вкладку **History**, кликните правой кнопкой по последнему коммиту →
   **Create Tag…** → введите `v1.0.0` (с буквой v) → **Create Tag**.
2. Нажмите **Push origin** (сверху). Метка уйдёт на GitHub и запустит сборку.
3. На GitHub во вкладке **Actions** появится запуск **Release** — подождите 15–25 минут до зелёной галочки.
4. Откройте раздел **Releases** (справа на главной странице проекта). Там будет **черновик (Draft)** с файлами:
   установщик, портативный архив и `SHA256SUMS.txt`.
5. **Скачайте установщик из этого черновика и проверьте его на своём компьютере**, как делали с моим.
6. Всё хорошо — нажмите карандаш (**Edit**) → при желании допишите описание → **Publish release**.
   Теперь любой может скачать файлы со страницы Releases.

## Что увидят пользователи
- На главной странице проекта — `README` и список папок. Так выглядит любой проект с открытым кодом: это исходный
  код, он нужен, чтобы любой мог убедиться, что приложение не отправляет данные.
- Скачивать им нужно **не папки**, а файлы со страницы **Releases**: установщик и портативный архив.
  В портативном архиве лежат только `NEXUS.exe`, README и лицензия — без `docs`, `scripts` и прочего.
  (GitHub сам добавляет к каждому релизу строки «Source code (zip / tar.gz)» — их можно не замечать.)
- Если не хотите показывать исходники, GitHub для этого не подходит: у закрытого репозитория файлы релиза никто,
  кроме вас, не скачает.

## Следующие версии
Поменяйте номер версии в четырёх файлах (`package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`,
`crates/nexus-core/Cargo.toml`), допишите `CHANGELOG.md`, сделайте Commit, создайте новый тег (`v1.0.1`) и Push —
дальше всё то же самое. Номер версии и тег обязаны совпадать, иначе сборка остановится с понятным сообщением.
