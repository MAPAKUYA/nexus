# NEXUS — модель безопасности и результаты проверки (версия 1.0.0)

## Что приложение собирает и хранит
- Имя исполняемого файла активного окна и запущенных приложений (например, `chrome.exe`) и читаемое
  название из свойств этого файла (например, «Google Chrome»).
- Время: сколько приложение было в фокусе и сколько работало, по дням.
- Только момент последнего ввода (для определения простоя) — без самого ввода — и факт блокировки экрана.
- Настройки (порог простоя, флажки, язык, тема) и список исключённых приложений (имя exe и читаемое название).
- Иконки приложений (маленькие PNG, около 4 КБ каждая) — только если включена настройка «Показывать иконки
  приложений» (по умолчанию выключена). Иконка читается из самого exe-файла программы средствами Windows и
  хранится в той же локальной базе; никуда не передаётся. Для магазинных (UWP) приложений иконка может быть
  общей, а у приложений без иконки в файле её не будет. При исключении приложения и при удалении статистики
  иконки удаляются.
- Копия выбранной темы («system», «light» или «dark») в локальном хранилище окна интерфейса (WebView2) —
  только чтобы применить тему до первой отрисовки; другие данные там не хранятся.

**Не собирается:** нажатия клавиш, содержимое и заголовки окон (читается лишь длина заголовка, чтобы
отличить настоящее окно от служебного), буфер обмена, скриншоты, файлы, пароли, сетевой трафик.

Всё хранится в одном файле `%APPDATA%\app.nexus.tracker\nexus.sqlite3` (папка профиля пользователя; доступ
по умолчанию только у вас и администраторов). Шифрования файла нет.

## Сеть
Собственный код приложения не содержит сетевых вызовов. Подтверждено:
- поиском по исходникам (сокеты, HTTP-клиенты, WinHTTP/WinInet, запуск процессов) — совпадений нет;
- в `NEXUS.exe` нет импорта `ws2_32`, `winhttp`, `wininet`, `iphlpapi`, `crypt32` и функций сокетов;
- в графе зависимостей для Windows нет `reqwest`/`hyper` (они подключаются Tauri только для Android и iOS);
  `tokio` включён без сетевой функции (`net`): только файлы, задачи и синхронизация;
- в интерфейсе нет `fetch`, `XMLHttpRequest`, `WebSocket`, внешних скриптов, стилей, шрифтов и картинок;
  политика CSP разрешает только свои ресурсы и внутренний канал `ipc`.

**Что показал замер на реальном компьютере (Windows, 60 с, окно открыто):** ни одного соединения с другими
компьютерами. Движок окна (WebView2) держал два соединения с `::1:80` — это петля на сам компьютер (вероятно,
предварительное соединение движка с внутренним адресом приложения `tauri.localhost`), данные они никуда не
передают. Со свёрнутым в трей приложением сокетов нет вообще.

**Важная оговорка.** Окно приложения рисует Microsoft Edge WebView2 — отдельный компонент Windows, не
наш код. Он может сам обращаться к серверам Microsoft (обновления, телеметрия — по настройкам Windows).
Чтобы это ограничить, окно запускается с ключами `--disable-background-networking`,
`--disable-component-update`, `--disable-sync`, `--no-pings`, `--disable-domain-reliability` и отключённой
SmartScreen-проверкой внутри окна. Проверить фактическую картину можно скриптом `scripts/verify-windows.ps1`.

## Установщик
Установщик (NSIS, сборка Tauri) ставит программу для текущего пользователя в `%LOCALAPPDATA%\NEXUS`, права
администратора не нужны. Он пишет в реестр: стандартную запись «Установка и удаление программ» и
`HKCU\Software\NEXUS\Language` (выбранный язык — приложение читает его только при первом запуске).
При настоящем удалении убираются запись автозапуска (`...\Run\NEXUS`), ключ языка и ярлыки; статистика остаётся,
если не отметить «удалить данные приложения». При обновлении поверх старой версии автозапуск и язык сохраняются.
Установщик проверен запуском в Wine (тихий режим): состав файлов, ключи реестра, режим обновления, настоящее
удаление, сопоставление 8 языков (11 из 11 случаев). Установщик из CI докачивает WebView2, если его нет.

## Права
- Права администратора не запрашиваются и не нужны.
- Окну выдано **ноль** разрешений Tauri (`capabilities/default.json`: `"permissions": []`), удалённым
  адресам IPC недоступен (нет раздела `remote`). Плагинов Tauri нет (ни `fs`, ни `shell`, ни `http`, ни `updater`).
- Приложению доступны только его собственные команды: `report`, `current_status`, `get_settings`,
  `save_settings`, `clear_statistics`, `take_notice`. Все входные значения проверяются (период — из
  списка, даты — строгий разбор календарной даты, настройки — приводятся к допустимым границам).
- Запись в реестр: единственное значение `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\NEXUS`, только
  когда вы включаете автозапуск; выключение его удаляет. Путь заключён в кавычки.
- Произвольные команды ОС не выполняются: код не запускает процессов.

## Небезопасный код
`unsafe` есть только в слое вызовов Win32 (`src-tauri/src/platform.rs`); в ядре (`nexus-core`) и в
`main.rs` его нет. Каждый блок снабжён пояснением `SAFETY`; хэндлы закрываются сразу после использования.

## Зависимости
- Rust: 420 пакетов в `Cargo.lock` (в основном Tauri/WebView2 и их компоненты). Прямых зависимостей у
  собственного кода три: `rusqlite` (SQLite встроен), `serde`, `windows-sys`; плюс `tauri`.
  `cargo audit` (база RustSec, 1386 записей, на дату проверки): **уязвимостей 0**, предупреждений 2 —
  `proc-macro-error` (не поддерживается) и `glib` (замечание о корректности); оба принадлежат Linux/GTK-части
  Tauri и в Windows-сборку не входят.
- npm (в приложение попадают react, react-dom, @tauri-apps/api и 3 мелких пакета): `npm audit` — **0 уязвимостей**.
- Сборка воспроизводима: `Cargo.lock` и `package-lock.json` зафиксированы, сборка идёт с `--locked`.

## Известные ограничения и принятые риски
1. Файл не подписан цифровой подписью → SmartScreen может предупреждать при первом запуске.
2. База не зашифрована (как и любые файлы вашего профиля).
3. CSP содержит `style-src 'unsafe-inline'` (нужно для стилей, которые React задаёт из кода). Все
   страницы локальные, динамического HTML из внешних источников нет, поэтому риск минимален.
4. Имя мьютекса единственного экземпляра может занять другая программа этого же пользователя — тогда
   NEXUS просто не запустится (отказ в обслуживании без утечки данных).
5. Clippy не запускался (в используемом репозитории его версия не совпадает с компилятором).
6. Проверки на реальной Windows (запуск, ключи WebView2, сетевая картина) выполняются вами — см. `scripts/verify-windows.ps1`.
